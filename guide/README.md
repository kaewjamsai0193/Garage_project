# คู่มือสร้างระบบจัดการอู่ซ่อมรถ (เฟส 0–4)

โค้ดครบทุกไฟล์ พร้อมเหตุผลว่าทำไมถึงเขียนแบบนั้น — ไม่ใช่แค่ "ทำอะไร" แต่เป็น "ทำไม"

ชุดนี้พาทำถึง **ใบสั่งซื้อ + รับของเข้าคลัง** (เฟส 4) เฟส 5–10 ฉบับเก่าเก็บไว้ที่ [`_later/`](_later/README.md) ยังไม่ได้ปรับตามโครงใหม่

## กติกาของคู่มือชุดนี้

1. **แต่ละเฟสเขียนเฉพาะของที่เฟสนั้นใช้** ไม่มีคอลัมน์ ฟังก์ชัน หรือปุ่ม "เผื่อไว้ก่อน" ให้เฟสหลัง
   เฟสหลังต้องการอะไรเพิ่ม ค่อยกลับมาเติม (เฟส 4 เป็นตัวอย่างจริง: ต้องแก้ตาราง Lot ของเฟส 3 ผ่าน migration)
2. **โค้ดทุกเฟสถูกรันจริงแล้ว** เทสต์เขียวและ `npm run build` ผ่านทุกเฟส ถ้าพิมพ์ตามแล้วพัง ให้เทียบกับคู่มือทีละบรรทัดก่อน
   **ยกเว้นหน้าจอเฟส 4 (ข้อ 7-15)** ที่เขียนใหม่เป็น TanStack Query + react-hook-form แล้ว และผ่าน `npm run build`
   แต่ยังไม่ได้กดทดสอบกับ backend จริง (เฟส 4 ยังไม่ได้ลงมือทำ) — ถ้าเจอจุดพังตอนทำ ให้แก้ในคู่มือด้วย
3. **backend แบ่งโฟลเดอร์ตามโดเมน** ตรงกับโปรเจ็คต้นทาง `../../project` (ดูหัวข้อถัดไป)

## โครงไฟล์ backend: หนึ่งโดเมนหนึ่งโฟลเดอร์

```
backend/app/
  main.py         สร้างแอป รวม router
  db.py           ต่อฐาน · get_db · get_or_404 · lock_shop
  auth.py         รหัสผ่าน · JWT · current_user · require_role
  models.py       ทุกตาราง (ไฟล์เดียว เพราะตารางอ้างกันไปมา)
  money.py        สูตรเงิน (Decimal)
  textutil.py     digits()
  schemas.py      ของกลางที่ทุกโดเมนใช้: In · Out · ReasonIn · serialize_for_role
  users/          auth_router.py · router.py · schemas.py · service.py
  settings/       router.py · schemas.py · service.py
  stock/          router.py · schemas.py · service.py
  purchasing/     router.py · schemas.py · service.py
```

หนึ่งคำขอเดินผ่าน 3 ไฟล์ **ในโฟลเดอร์เดียวกัน**:

| ไฟล์ | หน้าที่ |
|---|---|
| `<โดเมน>/router.py` | URL + ตรวจบทบาท (`require_role`) → เรียก service → คืน schema · อ่านข้อมูลธรรมดาได้ แต่**ห้ามเขียน** |
| `<โดเมน>/service.py` | กฎธุรกิจ ล็อก คำนวณ **และการเขียนข้อมูลทุกอย่าง** |
| `<โดเมน>/schemas.py` | รูปแบบข้อมูลเข้า-ออก · ต้นทุนแยก schema (`XxxAdminOut`) |

โดเมนหนึ่งเรียกอีกโดเมนด้วย import ตรง ๆ เช่น `from app.stock.service import products_by_id` — อ่านหัวไฟล์แล้วรู้ทันทีว่าพึ่งใคร

**ทำไมแบ่งตามโดเมน ไม่แบ่งตามชนิดไฟล์ (`routers/` `services/` `schemas/`)** — เวลาแก้เรื่อง "รับของ" ไฟล์ที่ต้องเปิดอยู่โฟลเดอร์เดียวกันหมด ไม่ต้องกระโดดสามโฟลเดอร์ และเห็นชัดว่าโดเมนไหนโตเกินไป

## หน้าจอ: สองท่าที่ใช้ทั้งระบบ

| เรื่อง | ใช้ | จำแค่นี้ |
|---|---|---|
| ดึงข้อมูลมาแสดง | TanStack Query `useQuery` | `useQuery({ queryKey: ["products", id] })` = `GET /products/{id}` (ตั้งไว้ใน `api.js`) |
| บันทึก / สั่งงาน | TanStack Query `useMutation` | สำเร็จแล้ว `invalidateQueries({ queryKey: ["products"] })` ทุกหน้าที่ใช้กุญแจนั้นโหลดใหม่เอง |
| ฟอร์ม | react-hook-form `useForm` | `{...register("ชื่อช่อง")}` + `handleSubmit((form) => save.mutate(form))` |
| ป๊อปอัพ | `<Modal>` / `<ReasonDialog>` | render = เปิด · เลิก render = ปิด |

อธิบายละเอียดครั้งแรกที่เฟส 1 ข้อ 11 (`api.js`) และข้อ 14 (`LoginPage`) · หน้ารายการตัวอย่างคือเฟส 2 ข้อ 17

## กติกาการเขียนโค้ด

- **ชื่อฟังก์ชันบอกว่าทำอะไร** ขึ้นต้นด้วยกริยา: `list_products` `get_product` `round_money` `formatMoney` `productStatus`
  ไม่ใช้ชื่อย่อที่ต้องเดา (`q2` `by_role` `run` `set`)
- **comment บรรทัดเดียวทุกฟังก์ชัน** บอกว่าทำอะไร รับจากไหน ส่งไปไหน — Python เป็น docstring · JS เป็น `//` เหนือฟังก์ชัน
- **เงื่อนไขยาวให้ตั้งชื่อก่อน `if`** เช่น `has_lots = ...` แล้วค่อย `if has_lots and ...`
- **จัดรูปแบบก่อน commit ทุกครั้ง** `ruff format` (backend) · `npm run format` (หน้าจอ) — ดู [commands.md](commands.md)

## ทำแบบแนวตั้ง

เฟสหนึ่ง = **หนึ่งเรื่อง ทำจบทั้ง backend และหน้าจอ**

```
เฟส N:  ตาราง → migration → เทสต์ (แดง) → service/router (เขียว) → หน้าจอ → กดจริงในเบราว์เซอร์ → commit
```

## ในแต่ละไฟล์มีอะไร

```
เป้าหมายของเฟส + ของที่ "ยังไม่ทำ" ในเฟสนี้
เฟสนี้ข้อมูลเดินยังไง — แผนผังภาษาคน 1 นาที ว่าข้อมูลมาจากไหน เก็บที่ไหน ส่งไปไหน
กฎที่ต้องเข้าใจก่อนเขียน
ส่วน backend    ตาราง → migration → schemas → service → router → เทสต์
ส่วนหน้าจอ      คอมโพเนนต์กลาง → หน้าจอ → route
เช็คว่าเฟสนี้เสร็จ + git commit
```

ไฟล์ที่เขียนใหม่ทั้งไฟล์ให้โค้ดเต็ม ไฟล์เดิมที่แก้ บอกเป็น **"เติม"** (ต่อท้าย) หรือ **"แก้"** (ของเดิม → ของใหม่)

## วิธีทำงานแต่ละเฟส

1. อ่านหัวข้อที่เฟสบอกใน `new_scenario_summary.md` และ `data_model.md`
2. แก้ `models.py` → `alembic revision --autogenerate` → **เปิดอ่านไฟล์ที่ได้ทุกครั้ง** → `alembic upgrade head`
3. **เขียนเทสต์ก่อน** ให้แดง แล้วค่อยเขียน service/router ให้เขียว
4. `docker compose run --rm api pytest` ทั้งชุด ห้ามมีอันเดิมพัง
5. ทำหน้าจอ → `npm run build` ผ่าน → เปิดเบราว์เซอร์กดจริง ทั้งจอคอมและย่อเป็นมือถือ
6. `ruff check --fix` + `ruff format` + `npm run format`
7. commit หนึ่งครั้งต่อเฟส

**ห้ามข้ามเฟส** เฟสหลังใช้ของเฟสหน้าหมด
