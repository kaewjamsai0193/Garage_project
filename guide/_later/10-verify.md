## 19 กรณีตรวจรับ

รายการเต็มอยู่ท้าย `data_model.md` หัวข้อ "กรณีตรวจรับ" — ทำมาครบทุกเฟสแล้วเทสต์พวกนี้ควรมีอยู่แล้ว เฟสนี้คือไล่เช็คว่าไม่มีข้อไหนตกหล่น

| ข้อ | เรื่อง | ไฟล์เทสต์ | เขียนในเฟส |
|---|---|---|---|
| 1 | ของไม่พอ อนุมัติไม่ได้ สต็อกไม่เปลี่ยน · ช่างกดอนุมัติไม่ได้ · เริ่มซ่อมก่อนอนุมัติไม่ได้ | `test_jobs.py` | 5 |
| 2 | FIFO ข้าม Lot ต้นทุนตรง ไม่ตัดซ้ำตอนออกบิล | `test_stock.py` | 3 |
| 3 | ใบกำกับซื้อ 856 → VAT 56 ต้นทุน 800 · เลขซ้ำไม่ได้ | `test_purchasing.py` | 4 |
| 4 | 3,800 → ฐาน 3,551.40 VAT 248.60 · ค่าเริ่มต้นอย่างย่อ | `test_billing.py` | 6 |
| 5 | ยกเลิกบิลก่อนรับเงิน สต็อกไม่เปลี่ยน เลขใหม่ ต้นทุนเท่าเดิม ออกซ้อนไม่ได้ | `test_billing.py` | 6 |
| 6 | รับเงินมีหัก ณ ที่จ่าย ปิดงาน ตั้งประกัน +30 วัน สร้างรอบเตือน +6 เดือน | `test_billing.py` `test_reports.py` | 6, 8 |
| 7 | ยกเลิกอนุมัติ ของคืน Lot เดิม ไม่เกิด Lot ใหม่ | `test_jobs.py` | 5 |
| 8 | กลับมาเปลี่ยนก่อนกำหนด รายการเก่าเป็น replaced เหลือค้างรายการเดียว | `test_reports.py` | 8 |
| 9 | ขายหน้าร้าน ของไม่พอ / ช่างขายไม่ได้ / ส่วนลด / เต็มรูป / 600−100 → 467.29 + 32.71 / ยกเลิกคืนของครั้งเดียว | `test_billing.py` | 6 |
| 10 | ยกเลิกใบงานต้องมีเหตุผล · อนุมัติแล้วยกเลิกไม่ได้ · รถมีงานค้างเปิดใหม่ไม่ได้ | `test_jobs.py` | 5 |
| 11 | ช่างหลักสองคน / ไม่ใช่ช่าง / ไม่มีช่างหลัก / งานเสร็จแล้วเปลี่ยนช่าง | `test_jobs.py` | 5 |
| 12 | เต็มรูปงานซ่อม ข้อมูลไม่ครบถูกปฏิเสธ · 1,070 → 1,000 + 70 | `test_billing.py` | 6 |
| 13 | ช่างออก PO ไม่ได้ · PO ไม่มีรายการ · สินค้านอก PO · ยกเลิกต้องมีเหตุผล | `test_purchasing.py` | 4 |
| 14 | สั่ง 10 รับ 6 → ค้าง 4 → รับ 5 ปฏิเสธ → รับ 4 → ปิดเอง → รับต่อไม่ได้ | `test_purchasing.py` | 4 |
| 15 | PO ที่รับแล้วยกเลิกไม่ได้ ปิดก่อนครบได้ · สองคำสั่งพร้อมกันไม่เกินยอดสั่ง | `test_purchasing.py` | 4 |
| 16 | งานเคลม ราคา 0 ตัด Lot จริง บิล 0 กำไรติดลบ ไม่ตั้งประกันใหม่ ไม่นับผลงาน | `test_claims.py` | 7 |
| 17 | เคลมจากบิลหน้าร้าน/รถอื่น/ยังไม่จ่าย/ยกเลิก/หมดประกัน · ตรงวันได้ วันถัดไปไม่ได้ · ไม่กรอกอาการ | `test_claims.py` | 7 |
| 18 | งานเคลมเปลี่ยนน้ำมันเครื่อง → สร้างรอบใหม่ ปิดรอบเดิมเป็น replaced | `test_reports.py` | 8 |
| 19 | ยอดหักที่เสนอ 30.00 / ลด 428 → 27.00 / หน้าร้านและเคลม 0 / แก้ยอดได้และยังตรวจผลรวม | `test_billing.py` | 6 |

**ข้อที่คนมักทำไม่ครบ**
- **ข้อ 1 และ 5** — "ได้ 409" ไม่พอ ต้องพิสูจน์ว่า**สต็อกไม่ขยับ**
- **ข้อ 7** — ต้องเช็ค `len(lots) == 1` ไม่ใช่แค่ยอดรวมถูก
- **ข้อ 9** — "ยกเลิกซ้ำไม่ได้" และ "คืนเข้า Lot ครั้งเดียว" เป็นคนละเรื่องกัน ต้องเช็คทั้งคู่
- **ข้อ 15 ท่อนหลัง** — สองคำสั่งพร้อมกัน คือเหตุผลทั้งหมดที่มี `lock_shop`
- **ข้อ 17** — ทดสอบทั้งสองฝั่งของเส้นแบ่งวัน (ตรงวัน = ได้ / เลยไปหนึ่งวัน = ไม่ได้)

## เดินด้วยมือในเบราว์เซอร์

ล้างฐานให้สะอาดก่อน แล้วเดินตามนี้ทั้งชุด
```
docker compose exec api python -m app.demo --reset
```

### สิทธิ์
- [ ] ล็อกอินครบ 3 role
- [ ] ช่าง: ไม่เห็นเมนูตั้งค่า บิล รายงานภาษี เตือน · ไม่เห็นต้นทุนที่ไหนเลย · ไม่มีปุ่มอนุมัติ
- [ ] พนักงาน: ไม่เห็นการ์ดการเงินบนแดชบอร์ด ไม่เห็นต้นทุน/กำไรบนบิล ไม่เห็นเมนูตั้งค่า
- [ ] **เปิด DevTools → Network ตรวจ response ของ `/api/dashboard`, `/api/invoices/{id}`, `/api/products/{id}/lots` ว่า role ที่ไม่มีสิทธิ์ไม่มีฟิลด์ต้นทุนติดมาเลย**
- [ ] พิมพ์ URL ของหน้าที่ไม่มีสิทธิ์ตรง ๆ → เด้งกลับ

### คลังและจัดซื้อ
- [ ] เพิ่มสินค้า ใส่สต็อกตั้งต้นสองรอบต้นทุนต่างกัน → เห็น Lot แยกสองอัน
- [ ] ปรับลดโดยไม่กรอกเหตุผล → ไม่ผ่าน
- [ ] ออก PO → พิมพ์ → **ตัวอย่างก่อนพิมพ์ไม่มีเมนูหรือปุ่มติดไปบนกระดาษ**
- [ ] รับของทยอย (สั่ง 10 รับ 6 แล้ว 4) → PO ปิดเอง
- [ ] รับของมีใบกำกับ → ต้นทุนแยก VAT ออกแล้ว · บันทึกเลขใบกำกับซ้ำ → โดนปฏิเสธ

### ใบงาน
- [ ] เปิดใบงานลูกค้าใหม่ และลูกค้าเก่า
- [ ] เปิดใบงานให้รถที่มีงานค้าง → **บอกเลขใบงานที่ค้างอยู่**
- [ ] ใส่อะไหล่เกินที่มี → กดอนุมัติ → ขึ้นข้อความไทยที่บอกจำนวน และ**สต็อกไม่เปลี่ยน**
- [ ] ยกเลิกอนุมัติ → ของกลับ Lot เดิม → แก้รายการ → อนุมัติใหม่
- [ ] พิมพ์ใบเสนอราคา → มีค่าแรงแยกแถว ยอดตรงกับหน้าจอ

### บิลและเงิน
- [ ] ออกบิลอย่างย่อ และเต็มรูป (ลองไม่กรอกเลขผู้เสียภาษี → โดนบล็อก)
- [ ] รับเงินที่มีหัก ณ ที่จ่าย → **อะไหล่ 3,210 + ค่าแรง 1,070 ต้องเสนอหัก 30.00 ลูกค้าจ่าย 4,250**
- [ ] งานปิดเอง วันหมดประกันขึ้น รายการเตือนถูกสร้าง
- [ ] ยกเลิกบิลก่อนรับเงิน → ออกใหม่ → **เลขใหม่ ไม่ใช้ซ้ำ**
- [ ] ขายหน้าร้าน → ยกเลิกบิล (ติ๊กยืนยัน) → **ของกลับ Lot เดิม จำนวน Lot เท่าเดิม**
- [ ] พิมพ์บิล → หัวกระดาษเป็นชื่ออู่ · มีวันหมดประกัน · มีบรรทัดหัก ณ ที่จ่าย

### ประกันและเคลม
- [ ] ประวัติรถแสดงแถบ "ในประกันถึง …"
- [ ] เปิดงานเคลม → ราคาเป็น 0 ทุกช่อง → อนุมัติ → **สต็อกหายจริง**
- [ ] ออกบิลยอด 0 → ยืนยันส่งมอบ → งานปิด → **วันหมดประกันยังเป็นของบิลเดิม**
- [ ] บิลเคลม (ดูเป็น admin) → **กำไรติดลบสีแดง**
- [ ] บิลขายหน้าร้านไม่ขึ้นให้เลือกตอนเปิดเคลม

### เตือนบำรุงรักษา
- [ ] รับเงินงานเปลี่ยนน้ำมันเครื่อง → รายการเตือนโผล่ วันครบกำหนดถูกต้อง
- [ ] กดปุ่มโทร → เปิดแอปโทรศัพท์
- [ ] จดโน้ต → บันทึก → รีเฟรชแล้วยังอยู่
- [ ] เปลี่ยนน้ำมันให้รถคันเดิมอีกรอบ → **รายการเก่าหาย มีรายการใหม่แทน**
- [ ] ขายน้ำมันหน้าร้าน → ไม่มีรายการเตือนเกิดขึ้น

### สรุปและรายงาน
- [ ] แดชบอร์ด: คิวงาน กราฟ สุขภาพสต็อก ผลงานช่าง มีข้อมูลครบ
- [ ] **กำไรเดือนนี้ลดลงหลังปิดงานเคลม**
- [ ] รายงานภาษี: ยอดขายตรงกับบิลที่ออกจริง · **บิลยกเลิกอยู่ในตารางแยกแต่ยังเห็น** · ภาษีซื้อตรงกับใบกำกับ

### หน้าจอ
- [ ] ย่อเป็นมือถือ (F12 → toggle device) แล้วใช้งานได้ครบทุกหน้า
- [ ] แถบเมนูอยู่ล่าง ปุ่มเพิ่มเป็นปุ่มกลมมุมขวาล่าง ป๊อปอัพเลื่อนขึ้นจากล่าง
- [ ] กด Esc ปิดป๊อปอัพได้ · กดปุ่มย้อนกลับของเบราว์เซอร์ปิดป๊อปอัพได้
- [ ] กด Tab ไล่ทั้งหน้าแล้วเห็นว่าโฟกัสอยู่ตรงไหนตลอด
- [ ] พิมพ์ทั้ง 3 แบบ (ใบเสนอราคา บิล ใบสั่งซื้อ) ได้ครบ

## เก็บงาน

```
git add -A
git commit -m "chore: acceptance pass"
```

**บั๊กที่เจอตอนเดินมือ แก้ที่ service ไม่ใช่แก้ที่หน้าจอให้มันดูเหมือนถูก**
หน้าจอที่ซ่อนปัญหาไว้ = ปัญหาเดิมที่หายากขึ้น

**ถ้าแก้อะไรก็ตาม ต้องรัน `pytest` ทั้งชุดใหม่ก่อน commit เสมอ** — เฟสหลัง ๆ พึ่งของเฟสก่อนหมด แก้ที่เดียวพังได้หลายที่

## จบแล้วทำอะไรต่อ

ของที่ระบบนี้**ตั้งใจไม่ทำ** (เขียนไว้ใน `new_scenario_summary.md` หัวข้อ "ขอบเขต") ถ้าวันหนึ่งต้องการจริงค่อยเพิ่ม:

- ทะเบียนผู้ขาย (ตอนนี้กรอกชื่อร้านสดทุกครั้ง)
- จองสินค้าล่วงหน้า
- มัดจำ / ผ่อนชำระ / ลูกหนี้
- หลายสาขา
- แปลงหน่วยสินค้า
- เชื่อม LINE

**ทั้งหมดนี้ไม่ได้ลืม แต่ตั้งใจตัดออก** เพราะอู่สาขาเดียวไม่ต้องใช้ และทุกอย่างที่เพิ่มคือของที่ต้องดูแลตลอดไป
